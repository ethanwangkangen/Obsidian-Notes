```cpp
// function
std::thread my_thread(f);

// lambda
std::thread ([](){
	f();
});
```
- f can be anything with function call operator
	- Function
	- Functor with `()` callable
	- Lambda

Be careful with most vexing parse! For passing a temporary functor in.
- `std::thread my_thread(background_task());`
	- Most vexing parse!

# Passing in arguments to threads
```cpp
std::thread my_thread(f, 5);
```
- Number of arguments
	- Must match exactly
	- Add the implicit `this` pointer as first argument if passing in member function pointer


### Thread arguments internals
- Threads store **copies** of arguments passed in. This a crucial point to take note.
- When the function takes in a reference parameter, we should use `std::ref()` on the argument in.

Phase 1 - construction
- **Decay-copy** each argument into thread-owned storage
	- References striped, top-level cv stripped, arrays become pointers, functions become function pointers
- The constructor takes forwarding references so it accepts lvalues and rvalues -> this determines how the internal copy is constructed

Phase 2 - invocation
- In the new thread, call the function with the stored copies, as if by `std::invok(std::move(f), std::move(copies)...)`
- Key point: the **arguments** arrive at your function as **rvalues**

Phase 3 - ordinary reference binding rules apply to those rvalues
- Parameter type T -> fine, moved from stored copy
- T& -> compile error, non const lvalue ref can't bind to rvalue. Need pass in `std::ref()`
- const T& -> compiles, but binds to stored copy, not original - silent no sharing

eg.
```cpp
void process(std::vector<int>& data);
std::vector<int> v{1,2,3};

std::thread t(process, v);            // ERROR: stored copy passed as rvalue,
                                      // vector<int>& can't bind to it
std::thread t(process, std::ref(v));  // OK: real reference to v
```
- Explanation
	- v is **decay-copied** into the thread storage
	- At invocation, the stored copy is passed as an rvalue, and `vector<int>&` cannot bind to an rvalue

Trap - const T&
- If the function parameter is `f(const T&)`, passing a direct reference **will work**, however it is actually binding to the **rvalue copy** instead of the original object.
	- So changes in the original reference will not be reflected, which is not what we intend.
	- So most likely we still want to use `std::ref()`

### Summary 
#### Reference parameters
```cpp
std::thread t (consume, std::ref(v))
```
#### Move types
- Move them in
```cpp
auto p = std::make_unique<Widget>();
std::thread t (consume, std::move(p));
```

#### Member function
```cpp
class OrderBook {
public:
    void process_feed(int feed_id);
};

OrderBook book;
std::thread t(&OrderBook::process_feed, &book, 42);
```

#### Conversions due to decay
- If a paramter type needs a conversion (eg. `char *` -> `std::string`), do it NOW in the calling thread.
	- If not, the conversion happens in the new thread using the copied pointer which may dangle already
```cpp
void f(int i, std::string const& s);
char buffer[1024];
// DANGER
std::thread t(f, 3, buf);

// correct
std::thread t(f, 3, std::string(buf));
```
- f takes in a `std::string`, and we have a `char []` which decays to `char *`
- If we just pass in the `char[]`, it will decay to `char *` and not convert to `std::string` until the new thread runs, at which point the pointer might already be dangling


>Rule: **convert to the final type yourself before passing** whenever an implicit conversion from a pointer/temporary is involved.

# detach/join
- Detach
	- Leave the thread running on its own, don't wait for it
- Join
	- Wait for thread to finish
	- Cleans up storage associated with the thread
		- `std::thread` object no longer associated with this now-completed thread
		- The `std::thread` object is no longer joinable, and `joinable()` returns false
- Note: if we don't decide one of these before the std::thread object is destroyed, the program is **terminated**
	- **MUST call one of these functions!**

- Be careful of **dangling references/pointers** when using detach
	- eg.
```cpp
struct func {
	int& i_; // captured by reference
	func(int& i) : i_(i) {}
	
	void operator() ()
	{
		do_something(i);
	}
};

void oops () {
	int i {5};
	func myFunc(i); // pass in reference
	std::thread myThread(myFunc);
	myThread.detach; // DANGEROUS! Dangling reference
}
```
- Thread detaches
	- i is captured by reference but thread may still be running after oops() terminates and i goes out of scope

### Considering exceptions when waiting
- In general, if calling `.join()` in **non-exceptional** case, we ALSO need to call it in the case of exceptions
```cpp
std::thread t(myFunc);
try {
	do_something_in_current_thread();
} catch (...) {
	t.join();
	throw;
}
t.join(); // here too
```
- Alternative
	- Instantiate a custom thread guard object, that takes in a thread by reference and calls the `.join()` on it in its **destructor**
	- Delete copy construtor and assignment to ensure not auto provided by compiler
```cpp
class thread_guard
{
private:
	std::thread& t_;
public:
	thread_guard(std::thread t) : t_(t) {}
	thread_guard(const thread_guard&) = delete;
	thread_guard& operator=(const thread_guard&) = delete;
	~thread_guard() {
		if (t.joinable()) t.join();
	}
};
```
- Can consider having the thread_guard **take ownership** of the thread and **move it in** too
- `std::thread t_;`
- `thread_guard(std::thread t) : t_(std::move(t)) {}`
  
### Threads in background
- Call `.detach()`
	- eg. Opening a new documnet. The thread handling the request doesn't need to care about waiting for that other thread to finish


# Threads are move-only
```cpp
std::thread t1 (some_function);
std::thread t2 = std::move(t1);
```
- If a thread already has some associated thread, trying to move into it will terminate the program
	- For consistency with the `std::thread` destructor.
	- Must explicitly wait for a thread to complete/detach it before destruction
		- The same applies to assignment

## Can return threads from functions
```cpp
// rvalue returned
std::thread f() {
	void f();
	return std::thread(f);
}

std::thread g(f());
```
- Remember that thread only have move constructors
	- If we return from a function,
	- The return value is treated as an rvalue (standard says that return of a **local variable** treats expression as rvalue)
		- Hence move constructor works with it

# jthreads (C++ 20)
- Joining thread
- Automatically join in the destructor

```cpp
#include <thread>
#include <utility>
 
class joining_thread {
    std::thread t;
 
public:
    joining_thread() noexcept = default;
 
    template <typename Callable, typename... Args>
    explicit joining_thread(Callable&& func, Args&&... args)
        : t(std::forward<Callable>(func), std::forward<Args>(args)...) {}
 
    explicit joining_thread(std::thread t_) noexcept
        : t(std::move(t_)) {}
 
    joining_thread(joining_thread&& other) noexcept
        : t(std::move(other.t)) {}
 
    joining_thread& operator=(joining_thread&& other) noexcept {
        if (joinable())
            join();
        t = std::move(other.t);
        return *this;
    }
 
    joining_thread& operator=(std::thread other) noexcept {
        if (joinable())
            join();
        t = std::move(other);
        return *this;
    }
 
    ~joining_thread() noexcept {
        if (joinable())
            join();
    }
 
    void swap(joining_thread& other) noexcept {
        t.swap(other.t);
    }
 
    std::thread::id get_id() const noexcept {
        return t.get_id();
    }
 
    bool joinable() const noexcept {
        return t.joinable();
    }
 
    void join() {
        t.join();
    }
 
    void detach() {
        t.detach();
    }
 
    std::thread& as_thread() noexcept {
        return t;
    }
 
    const std::thread& as_thread() const noexcept {
        return t;
    }
};
```
