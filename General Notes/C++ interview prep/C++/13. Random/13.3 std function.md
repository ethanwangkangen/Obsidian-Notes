- First generates the object/stores the pointer
	- If pass in functor/closure, generates the object
	- If not, just stores the pointer
	- On the heap if large, else just stored within the std::function object
		- SBO
		- Large example: stateful lambda with large capture
- Then stores a pointer to the hidden object
	- So we can call the method (type erased) virtually
	- The template holds your callable as a member and exposes it through a virtual invoke, so calls work without knowing the type

```cpp
struct CallableBase {
    virtual int invoke(int x) = 0;
    virtual CallableBase* clone() const = 0;   // "make another one of me"
    virtual ~CallableBase() = default;
};

template <class F>
struct Callable : CallableBase {
    F f; // the thing you gave us
    explicit Callable(F g) : f(std::move(g)) {}
    int invoke(int x) override { return f(x); }
};

class function {
    CallableBase* impl_;
public:
    int operator()(int x) { return impl_->invoke(x); }
};
```
- As can be seen by the `impl_->invoke(x)`
	- This is a virtual function call -> no inlining, vtable indexing, jump -> high overhead cost

## Copying and destroying
- std::function is copyable
	- Needs to duplicate whatever it's holding
	- SO whatever passed in also needs to be copy-constructible
	- eg. this does not work
```cpp
auto p = std::make_unique<int>(5);
std::function<int()> fn = [p = std::move(p)]{ return *p; };   // ERROR
```
- The closure holds a `unique_ptr` so it isn't copyable, so `clone()` fails to compile
